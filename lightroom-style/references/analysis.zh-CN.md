# 测量与摄影判断

[English](analysis.md) · 简体中文

分区色彩通常直接读取图片，并结合[影调与色彩解释指南](tonal-color.zh-CN.md)，无需额外插件或界面操作。本指南描述的是**渲染图文件测量**，不是Lightroom原生直方图。明暗占比必须与各区的颜色分布结合；全局配色或单个Lab中位数可能掩盖混色。尊重用户明确提出的仅用原生要求；原生界面读取保留为可选核对路径。

## 输入与输出约定

```text
python scripts/analyze_images.py --references REF1.png REF2.png --targets CURRENT_EXPORT.jpg --output NEW_REPORT.json
```

复用未变化的参考报告和当前导出图，完整直方图数组留在磁盘，仅读取简短摘要。

`scripts/analyze_images.py` 读取渲染后的 8-bit SDR JPEG、PNG、TIFF、WebP 和 BMP 图像。它不会解码相机 RAW、编辑图像或控制 Lightroom。它会写入一份新的 JSON 报告，并拒绝覆盖该报告。只分析明确提供的文件，绝不递归扫描个人照片库。

嵌入式 ICC 配置文件通过 Pillow LittleCMS 在内存中转换为 sRGB。转换错误属于失败，不能因此丢弃配置文件。未标记的图像会注明假定采用 sRGB；带有明确非 sRGB gamma/色度信息的未标记 PNG 会被拒绝。未知色彩管理或广色域工作流可能需要先生成原生标准化预览。EXIF 方向在内存中应用；透明和部分透明样本会被排除，且不会添加背景。

转换为 8-bit sRGB 可能裁剪超出色域的颜色；脚本不会单独量化这一点。因此，渲染结果中的端点不能证明原始图像或 Lightroom 内部处理流程发生了裁剪。

已知的高位深图像、不支持的模式、多帧/MPO 文件以及某些 HDR 增益图会被拒绝。HDR 检测并不完整：成功解码不能证明输入是 SDR。原生 SDR 预览是测量代理，绝不能替代编辑源或用户要求的高质量输出格式。

确定性的最近邻采样网格最长边最大为 1400 像素，且不会放大小图像。这样可以避免插值颜色，但可能漏掉小面积高光和纹理。在 100% 缩放下目视检查颗粒、锐化、色带和边缘。比例是样本估计值，不是全分辨率精确计数。

## 调滑块前的视觉判断

用简短的“图像证据 → 目标适配 → 验收”说明，按感知重要性排序；不能只列“青色、暖白、颗粒”这样的配色词。

1. **光线结构：**指出受光主体、阴影体块、最亮的重要表面及过渡。参考是强烈分离、漫射高调，还是平淡低反差？哪些来自场景光线／构图，哪些可以通过调色迁移？按材质选择参考；暖石墙不意味着所有天空都应变暖。
2. **将影调与颜色分开：**分别判断黑位深浅、漫反射白色是否明亮、镜面高光、主体区域的明暗跨度以及边缘／细节反差。低饱和不等于低对比，柔和边缘不等于压平明暗。边框接近纯黑时，中间主体仍可能发灰；全图中位亮度低可能只是暗部面积大。
3. **按材质和明暗角色分析色彩：**明确什么区域带色、浓度多强、哪些中性色应保持中性。“克制”可能只适用于天空，不适用于海水或赭黄椅子；不要因为一块区域低饱和就给整张图去色。
4. **质感优先级靠后：**颗粒、雾感和光学模糊与明暗分离是不同特征，不能用来弥补错误影调。蒙版只用于具体且必要的局部调整。

高反差参考应明确主体内部／附近的一个亮锚点和暗锚点；保留有意的深暗框景，也必须检查场景内部的分离。真正低反差的参考则保留较窄跨度，这不是“所有图都加对比”的新默认。

写入前用一句话指出最大偏差及调整方向。检查曝光、基本面板、总曲线／通道曲线和颜色分级亮度的合成效果。连续降低高光、白色及曲线白端点会把亮白压成灰；提阴影又抬黑端点会抹去暗锚点。除非参考支持改变，否则保护原图已有的明暗分离，不跨照片照搬参数。

### 可选的分区证据

全图直方图被黑色框景／混合光照主导，或用户指出发灰时，使用 `scripts/analyze_tone_regions.py`。从已经查看的图片中手动选少量归一化矩形：主体区域、重要受光／背光表面。目标原图与成片使用相同区域；参考图为可比材质单独选区。矩形可能混有多种内容，区域名称不等于自动分割。

```json
{"regions":[{"name":"shade","box":[0.1,0.2,0.3,0.4]},
            {"name":"lit","box":[0.5,0.2,0.7,0.4]}],
 "pairs":[{"name":"subject light/shade","dark":"shade","light":"lit"}]}
```

```text
python scripts/analyze_tone_regions.py --images BEFORE.jpg AFTER.jpg --regions REGIONS.json --output NEW_REPORT.json
```

工具只读，输出分区亮度分位数／跨度、Lab／饱和度中位数以及亮区减暗区的有符号中位亮度差。这些是编码 sRGB 证据，不是曝光挡数、微反差、自动区域、Lightroom 参数或风格评分；颗粒与物体边缘也会影响分区跨度。不能用全图跨度大证明主体有反差，也不要强迫不同场景达到同一差值或套用统一通过阈值。只在能解决疑问时做一次针对性测量。

验收时将参考、原生原图与成片以相近显示尺寸并列检查，再检查主体区域。黑边仍黑但中央受光区域变灰，属于影调退步。先修正最主要的视觉偏差，再微调颜色。参数回读／导出成功与风格匹配是不同结果；用户否定会覆盖之前的代理自行验收记录。


## 阅读报告

| 字段 | 含义 | 无效推断 |
| --- | --- | --- |
| `encoded_luma` | 伽马编码的 sRGB 亮度代理值（0–1）、分位数和 64 桶直方图 | Lightroom 的内部直方图或场景的物理亮度 |
| `linear_luminance_quantiles` | 经过 sRGB 逆传递函数后的相对亮度 | RAW 曝光或传感器动态范围 |
| `rendered_endpoint_fraction` | 渲染结果中近黑、近白和通道端点的比例 | 不可恢复的拍摄裁剪；红色物体可能自然达到某个通道端点 |
| `hsv_saturation_quantiles`, `lab_chroma_quantiles` | 颜色强度的两种度量 | Lightroom 滑块值或跨场景风格评分 |
| `hue` | 排除暗部、近中性和极亮样本的 12 个环形色相分箱；没有合资格像素时为 null | 语义对象，或证明绿色内容意味着绿色偏色 |
| `tonal_zones` | 固定亮度区间内的比例、Lab 中位数、低彩度内容与分区色相分布 | 皮肤/天空分割或光源识别 |
| `hue_fractions_of_zone`、`largest_chromatic_bins` | C* >12 的色相在该明暗区的采样面积估计；30° 一档，红色跨越 0°；分母包括低彩度样本 | 最大彩色分组一定是全区基调；精确原尺寸面积 |
| `low_chroma_fraction_of_zone` | C* ≤12 的区内占比；与各色相占比合计为 1，空区域为 null | 证明材质中性或没有轻微色偏 |
| `low_chroma_median_ab` | C* ≤12 且至少有 32 个样本时的 a*/b* 中位数 | 中性灰检测器或真实白平衡 |
| `reference_summary` | 按图像等权计算的中位数、MAD、最小值/最大值；基于文件 SHA-256 的精确去重 | 自动风格共识、异常值剔除或统计置信度 |

Lab 使用 sRGB → XYZ 和 D65 白点：L* 约为 0–100；a* 为正表示红色，为负表示绿色；b* 为正表示黄色，为负表示蓝色。不要将其直接与 D50 ICC PCS 值混用。影调区域使用编码亮度 <0.25、0.25–0.75 和 >0.75，而不是每张图像的分位数。样本稀疏的区域只能提供较弱证据。

同时查看中位数、MAD、范围和各张参考图像。样本量小、色彩管理未知、内容或光线不同以及参考图像相互冲突，都会削弱结论。两个明显不同的外观之间取平均，可能两者都不代表。精确哈希无法识别重新压缩的图像或视觉上近重复的图像；应通过视觉识别它们并降低其影响。

## 把观察结果转化为目标

只描述有证据支持的特征，例如：

| 观察到的特征 | 证据与一致性 | 针对目标的调整 | 候选控件 |
| --- | --- | --- | --- |
| 深阴影与明亮受光面 | 主体区域内也存在明确亮／暗锚点 | 保留强分离，同时保护重要细节 | 曝光、黑白端点、中间调曲线 |
| 确实存在的抬黑／压缩影调 | 视觉端点反复支持，不能从颗粒推断 | 仅在参考支持时适配较平缓影调 | 曲线端点、基本影调控件 |
| 偏暖高光与偏冷阴影 | 可比材质和光线支持该判断 | 避免全局蓝色偏色影响皮肤 | 颜色分级以及受支持的非生成式蒙版 |
| 低饱和的黄绿色植被 | 在包含植物的参考图像中反复出现 | 仅应用于相关的目标颜色 | HSL/颜色混合器 |

这些示例是推理格式，不是默认胶片预设。不要自动加入青绿色阴影、暖色高光、颗粒或哑光曲线。

语义判断必须查看图像；分析器没有分割能力。在相似光线下比较相似材质。对于数值化的区域比较，使用经过验证的非生成式选择区域或应用程序导出的区域，并说明所选样本。不要把区域统计标作整图证据。

已经调色的 JPEG 需要诊断当前像素。导入滑块值为零不代表图像未调色，且无法通过 Reset 恢复源图像。相似的亮度分布可能与截然不同的色相共存。应修正实际不匹配之处，而不是自动降低或提高曝光来追逐参考图像的中位数。

## 评估变化

前后比较时使用同一目标、裁剪、配置文件和 SDR 导出条件。先检查可读性、自然肤色、端点细节和局部边缘，再看数值相似度。然后评估是否出现了所请求的、可迁移的特征。编码可能引入小幅差异；不要要求测量结果完全一致。

不要把全局直方图距离作为唯一优化目标。白色背景人像和深色森林可以拥有相同的风格，同时具有不同的分布。避免强行让无关场景拥有相同的曝光、灰点、色温或饱和度中位数。

色彩管理实现：[Pillow ImageCms 文档](https://pillow.readthedocs.io/en/stable/reference/ImageCms.html)。转换后的分析像素永远不会写回源文件。
